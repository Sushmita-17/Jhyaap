01  EXECUTIVE SUMMARY
What is Jhyaap Station?
Jhyaap Station is a Kathmandu-based social commerce platform designed to bridge the gap between Nepal's rapidly growing social-media-driven discovery behavior and the fragmented, informal online ordering experience. It combines an e-commerce storefront, social sharing mechanics, AI-assisted ordering, multi-channel customer communication, and last-mile delivery management into a single integrated operating system.
The Problem
Customers in Nepal discover products on Facebook, Instagram, and TikTok but must DM individually to order — a slow, error-prone process.
Businesses manage orders via spreadsheets, WhatsApp messages, and manual calls with no centralized backend.
Delivery tracking is non-existent or communicated via phone call.
There is no loyalty or referral infrastructure to retain customers.
The Solution
A structured product catalog with real-time inventory, searchable by category, brand, or keyword.
Social commerce tools: shareable product links, customer stories, referral codes.
An AI chatbot that answers delivery, pricing, and offer questions 24/7.
Order lifecycle tracking: from placement to doorstep with live status updates.
Admin panel for complete business visibility: orders, analytics, offers, reviews, and delivery staff management.

06  SYSTEM DESIGN & ARCHITECTURE
6.1  Architecture Overview
Jhyaap Station uses a service-oriented monolith architecture in Phase 1 (single FastAPI application with clearly separated route groups), designed to be split into microservices in Phase 3+ as load demands.
Architecture Pattern
Modular Monolith → Microservices-Ready. All business logic lives in domain-specific modules (auth, products, orders, chat, social) within a single FastAPI application. Each module has its own router, service layer, and repository. This allows splitting into independent services without major refactoring.

6.5  Security Architecture
JWT Access Tokens: 15-minute expiry. Stored in memory (not localStorage) on frontend.
Refresh Tokens: 30-day expiry. Stored in HttpOnly cookie. Prevents XSS token theft.
OTP: 6-digit, 5-minute expiry, max 3 attempts, then 30-minute lockout. Rate limited per phone number.
Role-Based Access Control (RBAC): customer / admin / delivery_staff roles enforced at API middleware level.
Input Validation: Pydantic models on all FastAPI endpoints. SQL injection prevented by SQLAlchemy ORM.
Rate Limiting: Redis-backed per-IP and per-user rate limits on auth and chat endpoints.
CORS: Restricted to known frontend origins. Wildcard (*) disabled in production.
